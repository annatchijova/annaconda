Architecture

How it works, end to end

Follow one request — you click Ask the agent on a compromised endpoint. Here is everything it touches, in order. The rule to hold onto: the model decides what to investigate and how to describe it; the deterministic engine decides the verdict and seals it.

1

Your browser

You click a button. The page sends one request: "investigate this endpoint with the agent."

service/static → POST /investigate {mode:"agent", scenario:"attack"}
2

The backend, on Google Cloud Run

A small web service receives the request and sets up one investigation session, wired to this endpoint's telemetry. Then it hands the wheel to the agent.

service/app.py → investigate() → PurpleTeamSession
3

The agent — Gemini 3.5, via Vertex AI

The model reads your request and decides what to do. But it has no hands of its own: its entire power is four tools it can call. It cannot reach the evidence, the engine, or the seal directly — only through them.

agent/purple_team_agent.py → Google ADK Agent

This is the answer to "how does the agent have everything": it doesn't. It has four tools. The tools are the gateway.

↓ trust boundary ↓

Above this line the model is in charge — it chooses hunts and writes prose. Below it, everything is deterministic: no model, no floating-point, reproducible bit-for-bit. The model never crosses down.

4

Tool · run_hunt — freeze the evidence

Curated Velociraptor queries collect the endpoint's processes and connections. The result is frozen into an immutable evidence window, sealed with SHA-256. It returns a summary — not a verdict.

agent/tools.py → tools/velociraptor/adapter.py → collect_window()

The window's hash is computed with the same encoder the core uses everywhere — one source of truth for sealing.

5

Tool · adjudicate — the engine decides

The deterministic core scores the sealed window. Its cross-artifact engine (CAIE) notices the impossibility — a C2 beacon observed before its own process was created — and returns MALICE, mapped to MITRE T1070.006 and T1055.012. No model touched this number.

vigia_scorer.py → _vigia_score() → tools/caie.py
6

Seal it into the chain

The verdict is sealed onto the previous one — each entry commits to the last. Alter any window, any verdict, or the order, and verification fails. Re-running the same windows reproduces every seal exactly.

core/verdict_stream.py → build_stream_entry()
7

Back up to you

The sealed verdict returns to the agent, which now does the one thing it's for: it narrates the result in plain language — reporting the sealed facts exactly, never changing them. Your browser draws the exhibit: the seal, the timeline, the techniques, the custody chain.

Gemini narration → service/app.py → the exhibit UI
Least privilege

The agent's whole world: four tools

Everything the investigator agent can do. Its safety is structural — none of these lets it invent or change a verdict.

list_available_hunts()See the curated collections it may run. It cannot write its own query.
run_hunt(hunts, reason)Collect telemetry, freeze a sealed window. Returns a summary, no verdict.
adjudicate(window_id)Ask the deterministic core for the sealed verdict. It gets no way to pass a score or a hash.
verify_chain()Confirm the sealed record is intact.

Swap Gemini for any other model and the wording changes — the verdict never does. That is the whole design.

Investigator

Drives the hunt (/exhibit)

The agent above — chooses hunts, adjudicates, narrates the sealed result.

Mentor

Teaches juniors (/consult)

A second ADK agent with read-only tools: explains MITRE, verdict states, and methodology. Same rule — it guides, never decides.

The shape to remember: a request flows down through the agent, crosses the trust boundary once, and the deterministic core does the deciding and the sealing. The model orchestrates the investigation and puts the result into words — it is never the thing that says "this is malware." That sentence always comes from the sealed engine.
